# CÉRÉBRON ΑΩ — C44 CAMPAIGN INTELLIGENCE

Status: operational principle layered above C43.

## Root thesis
Intelligence in a campaign is not the number of messages, modules, workers, or internal steps.
It is the ability to adapt capabilities to the problem, allocate them where they have highest marginal value, compress redundant work, and produce more verified useful work per unit of interaction and compute.

## Core principle
RESULT > MESSAGE COUNT
USEFUL VERIFIED WORK > INTERNAL ACTIVITY
ADAPTIVE CAPABILITY ALLOCATION > FIXED PIPELINE
BATCH WHEN INDEPENDENT
SEQUENCE WHEN DEPENDENT
PARALLELISM MUST PAY RENT

## Campaign intelligence loop
CAMPAIGN
-> STUDY PROBLEM STRUCTURE
-> ESTIMATE WHICH CAPABILITIES MATTER
-> BUILD MINIMUM SUFFICIENT COGNITIVE PROGRAM
-> SPLIT INTO DEPENDENT AND INDEPENDENT WORK
-> BATCH / PARALLELIZE INDEPENDENT WORK
-> SEQUENCE DEPENDENT WORK
-> VERIFY OUTPUTS
-> FUSE / COMPRESS
-> MEASURE RESULT, COST, REGRET, COVERAGE
-> REALLOCATE CAPACITY
-> CONTINUE UNTIL STOP CRITERION

## Message compression principle
If 500 independent work units can be genuinely executed, checked, and fused in one campaign step, doing so is preferable to 500 sequential conversational turns.

However, one text message that merely describes 500 hypothetical executions is NOT equivalent to 500 real executions.

A work unit counts only if it has a real execution trace or a deterministic computation trace with identifiable input, output, status, and evidence.

## Worker equivalence rule
A batch of N verified independent executions can provide the throughput effect of N work units.
It must not be described as N AI agents unless N distinct AI/model executions actually occurred.

Deterministic GitHub Actions jobs = real compute workers, not automatically AI agents.

## Dynamic capability adaptation
For each campaign, estimate the expected value of available capabilities:
- reasoning
- representation change
- search
- calculation
- simulation
- verification
- transfer
- memory retrieval
- experimentation
- tool use
- parallel execution
- fusion
- red team

Activate only the coalition with positive expected marginal value.

## Productivity objective
Define campaign productivity conceptually as:

VERIFIED USEFUL OUTPUT / TOTAL CAMPAIGN COST

Cost may include:
- interaction turns
- compute
- tool calls
- external model calls
- memory use
- human intervention
- wall-clock time when meaningful

No single cost dimension is intelligence by itself.

## End-state evaluation
Whether a campaign was intelligent is assessed primarily by the final verified result under its constraints:
- Did it solve the target problem?
- Did it avoid unnecessary work?
- Did it detect and correct errors?
- Did it allocate effort to the true bottleneck?
- Did it transfer reusable capability forward?
- Did it outperform a simpler baseline at matched or explicitly accounted resources?

## Scale rule
1 task -> direct execution if sufficient.
10 tasks -> batch when independent.
100 tasks -> programmatic orchestration.
500-2000 tasks -> campaign compiler + workers + structured fusion.

Scale is not a goal. Scale is activated only when it improves verified campaign value.

## C44 law
INTELLIGENCE IS NOT HOW MUCH THE SYSTEM THINKS.
INTELLIGENCE IS HOW WELL THE SYSTEM CONVERTS AVAILABLE CAPABILITIES INTO VERIFIED RESULTS FOR THE CURRENT PROBLEM.

## Claim limit
C44 defines campaign-level orchestration and productivity criteria. It does not itself prove superintelligence, AGI, or autonomous cognitive improvement. Claims require measured outcomes and auditable execution evidence.
