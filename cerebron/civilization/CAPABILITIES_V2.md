# CEREBRON Ω — CIVILIZATION CAPABILITIES V2

Status: executable orchestration doctrine, not a claim of modified model weights or superintelligence.

## Absolute evidence rules

- CLAIM <= EVIDENCE
- REALITY > COHERENCE
- EVIDENCE > CONFIDENCE
- SIMULATION != TEST
- VERIFY BEFORE COMMIT
- ABLATION BEFORE ADDITION
- TRANSFER BEFORE GENERALITY
- Agent count != intelligence
- A role prompt != a distinct model

## New collective capabilities

### C1 — Cognitive Error Correction
Treat each proposed factual or logical claim as a redundant symbol that can be independently checked by other workers.

Protocol:
1. Extract atomic claims.
2. Require at least one independent challenge for any claim used in a final decision.
3. Record agreements, contradictions and unresolved claims separately.
4. Reconstruct the final answer only from claims surviving verification.
5. Never use majority vote as proof.

### C2 — Dynamic Cognitive Coalitions
Roles are not permanently fixed. For each subproblem, workers are grouped according to demonstrated usefulness on that task family.

Protocol:
1. Classify the subproblem.
2. Route to at least two complementary functions.
3. Add PROOF or REDTEAM when the claim is decision-relevant.
4. Reconfigure the coalition if disagreement persists.
5. Record which coalition solved the task.

### C3 — Strategy Memory
Memory stores successful and failed strategies, not only answers.

Each record contains:
- task family
- strategy used
- workers/models involved
- evidence obtained
- score/result
- failure mode
- transfer conditions
- confidence bounded by evidence

A strategy may be reused only when its transfer conditions match the new task.

### C4 — Contradiction Graph
Every contradiction becomes a first-class object.

Node types:
- claim
- evidence
- model output
- assumption
- test

Edge types:
- supports
- contradicts
- depends_on
- falsifies
- unresolved_with

High-value unresolved contradictions are routed before new idea generation.

### C5 — Proof / Red-Team Gate
Before a civilization-level result is integrated:
1. PROOF checks derivation, arithmetic, logic and evidence chain.
2. REDTEAM searches for counterexamples, hidden assumptions and alternative explanations.
3. EVALUATOR checks against a ground-truth or objective benchmark whenever possible.
4. Only surviving content is integrated into memory.

### C6 — Novelty Operators
Workers must not default to scale-only answers such as "more agents", "larger model", "more context" or "more data".

Use at least one operator:
- INVERT: reverse a core assumption.
- TRANSFER: import a mechanism from another scientific/engineering domain.
- EMERGE: derive global capability from local rules.
- CONSTRAINT: remove a resource and redesign around the loss.
- COUNTERFACTUAL: ask what architecture would work if the dominant paradigm were false.

Every novel proposal must include mechanism, measurable prediction and falsifier.

### C7 — Heterogeneous Model Routing
When several model families are available, assign tasks by measured benchmark strength rather than prestige or parameter count.

Track:
- exact task accuracy
- latency
- memory footprint
- failure type
- calibration
- complementarity with other models

Do not call two jobs using identical weights two independent model families.

### C8 — Capability Evolution Loop
For each completed task:
TASK -> DECOMPOSE -> DIVERSE SEARCH -> CONTRADICTION GRAPH -> ERROR CORRECTION -> PROOF/REDTEAM -> OBJECTIVE SCORE -> STRATEGY MEMORY -> ROUTER UPDATE

A capability improvement is accepted only if it improves a fixed benchmark or produces a validated new capability without regressing protected tasks.

### C9 — Ablation Discipline
Any claimed improvement must be compared against:
- best single model baseline
- matched-compute baseline when feasible
- previous architecture
- new architecture with each major component removed one at a time

No architectural component is retained solely because it sounds useful.

### C10 — Civilization Integration Rule
The civilization is treated as an institution of models, tools, memory, tests and evidence—not as one monolithic mind.

Integration requires:
- traceable source
- reproducible test when possible
- explicit uncertainty
- reversible decision
- stored failure modes
- no claim of superintelligence without benchmark evidence.

### C11 — Campaign Experience Replay
The civilization must reuse its own verified execution history instead of restarting from zero.

Protocol:
1. Build a provenance-preserving index from the persistent campaign state.
2. Separate execution success from scientific or logical validation.
3. Treat COMPLETED + result_ref records as review candidates until their evidence is audited.
4. Route recurring FAILED_RETRYABLE and QUARANTINED patterns into failure-memory and redesign work.
5. Route outcome-divergence groups to PROOF/REDTEAM before generating redundant hypotheses.
6. Use measured historical role/model outcomes to inform routing, never as a truth score.
7. Promote a historical strategy to validated Strategy Memory only after PROOF, REDTEAM and EVALUATOR gates.
8. Preserve result_ref and record hashes so every promoted memory can be traced back to its source.

Experience replay changes orchestration and memory use; it does not modify model weights by itself.
